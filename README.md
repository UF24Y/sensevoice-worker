# sensevoice-worker

RunPod Serverless(LOAD_BALANCER)용 SenseVoice 받아쓰기 워커.

## 왜 Whisper 에서 옮겼나

정확도 때문이 아니라 **고장의 성격** 때문이다.

Whisper 는 말소리가 없는 구간에서 침묵하지 않고, 학습 데이터(유튜브 자막)에
흔했던 문구를 지어낸다. 15초짜리 순수 사인파를 넣었더니 이렇게 답했다:

```
[00:00] 시청해주셔서 감사합니다.
```

보이스드라마처럼 숨소리·탄성 비중이 큰 자료에서는 그 구간이 통째로 오염된다.

SenseVoice 는 비자기회귀 모델이라 그런 식으로 헛돌지 않는다. 대신 그 구간을
음향 이벤트와 감정으로 표시한다. 덤으로 한국어가 정식 지원 언어(중국어·광둥어·
영어·일본어·한국어 5개 특화)라 CJK 정확도가 낫고, MIT 라이선스라 자체 호스팅이
가능해 음성이 외부로 나가지 않는다.

## 구조

Ollama 워커와 달리 nginx 가 없다. 그때는 스톡 이미지에 `/ping` 이 없어서 앞에
세워야 했지만, 여기서는 앱을 직접 짜므로 `/ping` 을 그대로 낸다.

| 경로 | 하는 일 |
|---|---|
| `GET /ping` | RunPod 헬스체크. **모델이 다 올라온 뒤에만** 200 을 준다 |
| `POST /transcribe` | 오디오 파일 하나 → 구간별 시각 + 텍스트 + 태그 |

`/ping` 이 준비 전에 200 을 주면 RunPod 이 트래픽을 넘겨 첫 요청들이 실패한다.
그래서 로딩 중에는 503 을 준다.

## RunPod 설정

- 타입: **LOAD_BALANCER**
- 이미지: `ghcr.io/uf24y/sensevoice-worker:latest` (**digest 로 고정할 것** — `:latest` 는 캐시된다)
- 환경변수: `PORT=80`, `PORT_HEALTH=80`
  - `env` 는 병합이 아니라 **교체**다. 하나만 바꿔도 나머지가 지워진다
- GPU: 작은 것으로 충분하다. 모델이 234M 파라미터라 VRAM 을 거의 안 쓴다

## 응답 형식

```json
{"segments": [
  {"start": 12.0, "end": 18.0, "text": "", "emotion": "", "events": ["숨소리"]},
  {"start": 20.0, "end": 24.0, "text": "문을 열자마자 알았죠.", "emotion": "두려움", "events": []}
]}
```

대사가 없고 `events` 만 있는 줄이 비언어 발성 구간이다. Whisper 였다면
비어 있거나 지어낸 문장이 들어갔을 자리다.
